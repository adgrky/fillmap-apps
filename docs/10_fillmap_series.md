# 埋め立てシリーズ設計書(共通エンジン+全アプリ個別仕様)

> 前提: 塗り鉄(railmap)設計書(railmap_master_plan.md)を「基底SPEC」とする。
> 本書は ①基底SPECからの共通エンジン拡張(§E)②各アプリの差分仕様(§A1〜A11)のみを定義する。
> 基底SPECと重複する事項(技術スタック・デザイントークン・保存設計・PWA・運用ルール)は再記述しない。

---

## §E. 共通エンジン拡張仕様(packages/core)

railmap の src/core を packages/core に昇格させ、以下の3モードを実装する。

### E1. 対象物モード
| モード | ジオメトリ | 塗り単位 | 使用アプリ |
|---|---|---|---|
| LINE | LineString | 路線/道単位(将来:区間) | 路線・国道・街道 |
| POINT | Point | 地点単位 | 山・道の駅・城・温泉・空港・マンホール・御朱印・SA/PA |
| POLYGON | Polygon | 区域単位 | 市区町村 |

エンジンはモードを設定JSONで受け取る。アプリ固有コードは「データ・称号定義・換算文言・テーマ色・文言」のみ。

### E2. POINT モード共通仕様
- 未訪問: グレー小円(zoom連動サイズ)/ 訪問済: テーマ色+グロー円+チェックアイコン
- タップ→ボトムシート: 名称/属性/[行った!]/訪問日/回数/メモ(140字)
- 塗りアニメ(W1): 円が一瞬拡大→波紋が広がる(500ms)+達成カウントアップ。基底SPEC §7.1 と同じ品質基準
- クラスタリング: 地点数500超のアプリは maplibre のクラスタ機能を使用(クラスタ円に「済/全」数を表示)
- リスト画面を追加(地図タブとは別タブ): 都道府県別アコーディオン一覧、チェックボックスで地図を開かず記録可能(W4: 入力ハードル最小化)

### E3. POLYGON モード共通仕様
- 区域タップ→塗り。塗り状態は多段階(後述 citymap 参照)で、段階ごとに色の濃度が変わる
- 塗りアニメ: 区域全体がテーマ色でフラッシュ→定常色へ(400ms)
- 境界線は常時表示(#3a3f4a, width 0.8)

### E4. 共通データモデル拡張
```ts
type SaveDataV2 = SaveData & {
  visits: { [targetId: string]: {
    level?: number;        // POLYGON用 0-5
    count: number; firstDate?: string; memo?: string;
    routes?: string[];     // 山用: ルート名履歴
  }};
};
```

### E5. 共通シェア画像
基底SPEC §10 と同一レイアウト。差分: 中央の数値表現をアプリ設定で注入
(例:「百名山 34/100」「全国市区町村 18.2%」)。
**統一フッターロゴ(00_master §3)を必ず使用。**

### E6. データ前処理共通基盤(tools/)
- `preprocess_point.py`: CSV(id,name,lat,lng,pref,attrs...)→ points.geojson + meta.json
- `preprocess_polygon.py`: 国土数値情報 N03 → 簡略化ポリゴン + meta.json
- LINE系は railmap の preprocess.py を汎用化
- **手動キュレーションデータは tools/curated/*.csv に置き、出典URLをヘッダコメントに必ず記録**(著作権・正確性の監査用)

### ⚠️ E7. データ著作権の共通原則
- 事実データ(山の名称・座標・施設名・住所)に著作権はないが、**他サイトのデータベースの丸ごと複製は不可**(データベース権)。一次情報(官公庁・自治体・公式団体)から収集し、出典を設定画面に明記
- 写真・ロゴ・カード画像(マンホールカード等)は**一切収載しない**

## §A1. 市区町村塗りつぶしマップ(citymap)【優先度:最高】

**一言**: 行った市町村を塗って、人生の行動範囲を一枚の絵にする
**市場**: 「経県値」「制県伝説」が県単位で実績を証明済み。市区町村単位(1,741)は粒度が細かく寿命が長い

### 勝ち筋
- W1: 塗った瞬間のフラッシュ+「全国 ◯◯/1741」カウントアップ
- W2: **塗りレベル制が本体**。0:未踏/1:通過/2:降り立った/3:歩いた/4:泊まった/5:住んだ(経県値方式の市区町村版)。レベル合計点「あなたの行動力スコア」を算出
- W3: 全国地図が点描画のように染まるシェア画像。**塗り数が少なくても「これから埋める余白」が映える構図**(余白が多い=伸びしろ、と文言でポジティブ化)
- W4: レベル別ワンタップ記録、リスト画面から一括入力可
- W5: 振り返り年表(年別に塗った自治体を表示)/ 消滅自治体(平成の大合併前)データ=マニア歓喜のプレミアム種
### データ
国土数値情報 N03(行政区域)。政令市は区単位。simplify は表示確認しつつ tolerance 調整(ポリゴンは重いので必須)。サイズ3MB超過時は地方ブロック別8分割遅延ロード
### 称号例
初上陸(1)/ 県内コンプ(いずれかの県100%)/ 離島マスター(島嶼自治体10)/ 全国1%クラブ / 半分来たぞ(50%)
### フェーズ
P0: N03前処理(受入: 自治体数が1,741±政令区で一致)→ P1: 塗り+レベル+保存 → P2: スコア/称号/シェア画像/PWA
指示例: `SPEC.md §E3,§E4,§A1を実装。基底SPECの品質基準準拠。受け入れ条件は各フェーズ記載`

## §A2. 百名山埋め立てマップ(yamamap)

**一言**: 登った山が光る、自分だけの登頂史
### 勝ち筋
- W1: 登頂記録時、山頂から光が立ち上るアニメ(山アイコンが点灯)
- W2: 換算文言=「累計標高 ◯◯m — エベレスト◯回分」(登頂山の標高合計)。百名山/二百名山/三百名山/都道府県最高峰の多層達成率
- W3: シェア画像に「34/100座・累計標高◯m」+日本地図の光る山々
- W4: ルート名・同行者メモ・複数回登頂の履歴(routes[])
- W5: 山行記録のCSVエクスポート(ヤマレコ等からの移行需要は逆輸入が難しいため、まず手入力34座を5分で終えられるリスト画面を最優先)
### データ
国土地理院「日本の主な山岳一覧」(約1,003山)から百名山・二百・三百・県最高峰をタグ付けして抽出。tools/curated/mountains.csv に整備(深田百名山リストは事実の列挙であり利用可。⚠️照合元URLを記録)
### 称号例
初登頂 / 3000m峰デビュー / アルプス制覇 / 半分の頂(50座)/ 百名山コンプリート(最高難度・金称号)
### フェーズ
P0: curated CSV作成+前処理 → P1: POINT塗り+リスト入力 → P2: 標高換算/称号/シェア
指示例: `SPEC.md §E2,§A2を実装`

## §A3. 道の駅埋め立てマップ(michimap)

**一言**: 全国1,200駅、日本一周スタンプラリーをポケットに
### 勝ち筋
- W1: チェック時に「スタンプを押す」演出(ポンッと判子型マークが地図に落ちる。効果音=スタンプ音)← このアプリだけ塗りアニメをスタンプ型に差し替え
- W2: 地方ブロック別達成率(北海道だけで120超→ブロック分けが「あと少し」を作る)/「制覇まであと◯駅」常時表示
- W3: スタンプ帳風シェア画像(押した判子が並ぶグリッド+地図)
- W4: 公式スタンプラリーと併用される前提→訪問日とメモを重視
- W5: 訪問回数ヒートマップ/廃駅・登録抹消駅データ
### データ
国土交通省 道の駅一覧(公式公表、全駅の名称・所在地)。国土数値情報にも道の駅データあり(⚠️最新性を両者比較して採用を決め VERIFIED.md に記録)。年1回の新規登録追従は手動更新で許容
### 称号例
道の駅デビュー / 北海道ブロック制覇 / 100駅クラブ / 全国制覇(金)
### 指示例: `SPEC.md §E2,§A3を実装。塗りアニメはA3記載のスタンプ演出に差し替え`

## §A4. 100名城埋め立てマップ(shiromap)

**一言**: 日本100名城+続100名城、攻め落とした城を旗で示せ
### 勝ち筋
- W1: 登城記録=城に**旗が立つ**アニメ(旗がスッと立ち上がる600ms)。「攻略」の語彙で統一(行った→攻略した)
- W2: 100名城/続100名城/現存12天守/国宝5城の多層達成率
- W3: シェア画像「◯◯城、攻略。(34/100)」城名を主役にした構図
- W4: 公式スタンプ帳ユーザーが移行しやすいよう、一覧画面は公式番号順ソート対応
- W5: 城データに「天守の形式・築城年・城主」属性を持たせ、攻略済の城だけ詳細が読める図鑑モード
### データ
日本城郭協会の100名城・続100名城リスト(名称・所在地は事実データ)。座標は地理院地図で照合し tools/curated/castles.csv に整備(計200点+現存12天守タグ)
### 称号例
初陣 / 現存天守ハンター(12)/ 国宝コンプ(5)/ 天下統一(200城・金)
### 指示例: `SPEC.md §E2,§A4を実装。文言は「攻略」系で統一`

## §A5. 国道完全制覇マップ(kokudomap)

**一言**: 国道459路線、走った道で日本に線を描く
### 勝ち筋
- W1: LINE モード=railmap の光走りアニメをそのまま流用
- W2: 総走破距離+「国道1号から458号まで、あと◯本」/ 酷道(険しい国道)タグで「酷道◯本走破」を別カウント(マニア直撃)
- W3: 走った国道だけが光る日本地図(railmapと同じ強み)
- W5: 酷道・旧道・海上国道(フェリー区間)の特殊タグ=プレミアム種
### データ
OSMから `route=road + ref=国道番号` で抽出(Overpass APIで一括取得→前処理。⚠️取得スクリプトとライセンス表記 ODbL を必須記載)。番号・総延長は道路統計年報で検証
### 称号例
国道デビュー / 一桁国道コンプ(1-9号)/ 酷道ハンター / 全国道制覇(金)
### 指示例: `SPEC.md §E1(LINE),§A5を実装。railmapのアニメ資産流用`

## §A6. 温泉めぐりマップ(onsenmap)

**一言**: 浸かった温泉地が湯けむりを上げる地図
### 勝ち筋
- W1: 記録時、地点から**湯けむりが立ち上るパーティクル**(CSS/Canvas、800ms)
- W2: 泉質別達成率(硫黄泉◯/単純泉◯…)で「全泉質コンプ」という収集軸を作る
- W3: シェア画像「今年◯湯、累計◯湯」(温泉は回数文化なので累計入浴数も主役に)
- W5: 泉質・効能の図鑑モード/共同浴場タグ
### データ
v1は「にっぽんの温泉100選」等の有名温泉地ベースではなく、**環境省 温泉利用状況・自治体公表の温泉地リストから主要温泉地300を curated CSV 化**(⚠️一次情報の選定根拠をVERIFIED.mdに)。個別施設単位はデータ維持が重いので「温泉地」単位とする(維持費ゼロ原則)
### 称号例
初湯 / 泉質コレクター(5泉質)/ 東北の湯めぐり(ブロック制覇)/ 百湯クラブ
### 指示例: `SPEC.md §E2,§A6を実装。湯けむり演出はA6記載`

## §A8. マンホールカード収集マップ(manholemap)

**一言**: 全国1,000枚超のマンホールカード、収集状況を地図で一望
### 勝ち筋
- W2: 弾(第◯弾)別達成率(コレクターは弾単位で追う)/配布場所が地図に出る=**収集計画ツールとしての実用価値**が継続利用を生む
- W3: 「◯◯弾コンプ!」シェア画像
- W4: 配布中止・配布場所変更が多い世界なので「情報は変わる場合があります。公式で確認を」を常設表示(信頼設計)
- W5: 入手日・入手方法メモ、ダブり所持数管理
### データ
GKP(下水道広報プラットホーム)公式サイトの配布一覧から **カード名・自治体・弾・配布場所名・座標** のみを curated CSV 化。**カード画像・デザイン説明文は著作物のため一切収載しない(§E7)**。年数回の弾追加は手動更新
### 称号例
初カード / 第1弾コンプ / 100枚コレクター / 都道府県横断(20都道府県)
### リスク注記
配布情報の鮮度劣化が宿命。設定画面に「データ基準日」を表示し、更新は弾追加時のみと割り切る
### 指示例: `SPEC.md §E2,§A8を実装。E7の著作権原則を厳守`

## §A9. 御朱印・神社仏閣マップ(goshuinmap)

**一言**: 参拝の記録と御朱印帳が、ひとつの地図になる
### 勝ち筋
- W1: 参拝記録時、朱印がポンと押される演出(道の駅と共通実装の色違い)
- W2: **このアプリだけ「自由ピン追加」を主役にする**(全国の寺社は16万超でプリセット不可能)。プリセットは一之宮・四国八十八ヶ所・西国三十三所など巡礼コース約300のみ
- W5: 巡礼コース別達成率(八十八ヶ所巡りはそれ自体が埋め立てコンテンツ)/御朱印メモ(墨書き・日付・初穂料)
### データ
プリセット: 各巡礼会公式サイトの札所一覧から curated CSV(事実データのみ)。それ以外はユーザーが地図長押しでピン追加(エンジンに「ユーザーPOI」機能を追加 ← **この機能は温泉・他アプリにも還元できる共通投資**)
### 称号例
初参拝 / 一之宮巡り10社 / 八十八ヶ所結願(金)/ 百社参り
### 指示例: `SPEC.md §E2,§A9を実装。ユーザーPOI機能はpackages/coreに実装し他アプリへ還元`

## 付録: 海外版方針(全LINE/POINT系共通)
- 日本版がジャンル内で月間アクティブ100人を超えたものだけ着手
- データはOSM抽出(ODbL表記)。鉄道海外版は国別パッケージ(まず台湾・韓国=日本の鉄道ファンと往来が多い)
- コードはi18n対応をPhase 2時点で仕込まない(YAGNI)。海外版決定時に文言だけ辞書化
