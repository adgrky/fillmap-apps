# 金融ツール群設計書(Streamlit / GitHub Actions 系)

> ケンの既存資産(stock-recommender の yfinance/EDINET/Streamlit ノウハウ)を最大流用する系統。
> 共通原則: 維持費0円 / **投資助言にあたる断定表現の禁止**(全アプリ共通の免責表示を§C0に定義)/
> ユーザー個別データを預からない(マルチユーザーのDB運用=維持費とリスク。各アプリの保存方式は個別に定義)。

## §C0. 系統共通仕様

### C0-1. 免責・コンプライアンス(全アプリのフッターに固定表示)
```
本アプリは情報提供を目的としており、投資助言・推奨ではありません。
投資判断はご自身の責任で行ってください。データには遅延・誤りが含まれる場合があります。
```
- 「買い」「売り」「推奨」の語を出力に使わない。「割安傾向」「条件合致」等の事実記述に統一
- データ出典(yfinance/EDINET)と取得時刻を常に表示

### C0-2. 技術共通
- Streamlit Community Cloud(public repo)/ Python 3.11 / yfinance / plotly
- キャッシュ: `@st.cache_data(ttl=86400)` を基本(無料枠のリソース保護)
- **st.session_state はセッション限り**。永続データが必要なアプリはCSV入出力で代替(ユーザーデータを預からない)
- 日本語UI。スマホ表示確認必須(Streamlitはモバイルが崩れやすい→ st.columns 多用禁止、縦積み基本)

### C0-3. Streamlit系の共通リスク(VERIFIED.md 必須項目)
- [ ] yfinance の取得可否は仕様でなく事実(Yahoo側変更で壊れる)。**実装前に対象データ(日本株・米株・配当・財務)の取得テストを行い、取れた/取れないを記録してから設計を確定**
- [ ] Community Cloud 無料枠の制限(スリープ・リソース)を確認し、起動時ロードを軽量化

## §C1. 米国株リサーチャー(us-stock)【系統の主力】

**一言**: とっつきにくい米国株を、日本語で・3分で・ざっくり正しく
### 勝ち筋
- **差別化=翻訳と要約の設計**。指標は必ず「日本語の意味+目安」を添える(例: PER 28倍 — 利益の28年分の値段。S&P500平均は約◯倍)。数字を出すだけのサイトとの差はここ
- 銘柄ページ構成(1画面縦積み): ①ひとこと事業説明(セクター・何で稼ぐ会社か)②株価チャート(1y/5y)③主要指標カード(PER/PBR/配当利回り/時価総額、各に目安コメント)④直近4四半期の売上・EPS推移棒グラフ ⑤配当履歴
- ランキングタブ: 配当利回り/PER低い順/出来高/年初来騰落(対象はS&P500構成銘柄に固定=リスト管理可能な範囲に限定)
- セクタータブ: 11セクター→該当銘柄一覧
- W3: 銘柄サマリーカード画像生成(plotlyのto_image。⚠️Cloud上でkaleidoが動くか確認)
- W5: ウォッチリスト(URLクエリパラメータに銘柄をエンコード=ブックマークが保存代わり。DB不要の発明として全Streamlitアプリに展開)
### データ
yfinance。S&P500構成銘柄リストはリポジトリ内CSVで管理(四半期ごと手動更新)
### フェーズ
P0: C0-3取得テスト → P1: 銘柄ページ → P2: ランキング/セクター → P3: カード画像/ウォッチリスト
指示例: `SPEC.md §C0,§C1。P0の取得テスト結果がVERIFIED.mdにあることを確認してから着手`

## §C3. 割安診断(NCAV)(neta-neta)

**一言**: 会社の解散価値より安く売られている株を、機械的にあぶり出す
### 勝ち筋
- **手法を1つに絞る**: グレアムのネットネット株(NCAV = 流動資産 − 総負債 > 時価総額×1.5 等の古典基準)。土地時価の再評価はv2以降(路線価突合は重い)
- 画面: ①銘柄入力→NCAV診断(流動資産・負債・時価総額の比較図解+「教科書的には割安圏/圏外」)②PBR/PER同時表示 ③スクリーニング(EDINET財務データ×全上場の一括判定は計算が重いので、対象を東証スタンダード・グロースの小型株に限定 or ユーザー入力銘柄リストのバッチ診断)
- W5: 診断ロジックの解説ページ(グレアム手法の教科書的説明)→ note記事と連携導線
### データ
ケン既存の EDINET モジュールを流用(XBRL→流動資産・負債)。yfinanceで時価総額
### ⚠️ 確認
EDINETから必要科目(流動資産合計・負債合計)が全対象で安定取得できるか、欠損率を実測してから対象範囲を確定
### 指示例: `SPEC.md §C0,§C3。modules/institutional.pyのEDINET実装を流用`

## §C4. 収支管理(trade-log)【既存資産の切り出し】

**一言**: トレードの通信簿。期待値がプラスになるまで、淡々と
### 勝ち筋
- 既存アプリのトレードログ機能を**ローカルファースト静的PWAとして再実装**(Turso不使用=他人に配ってもDB費用ゼロ。ケン個人用は既存Turso版を継続)
- 入力: 銘柄/IN価格/OUT価格/株数/日付/戦略タグ(任意)
- 表示: 勝率・損益率・**期待値 = 勝率×平均利益 −敗率×平均損失**(これを画面最上部のヒーロー数値に。プラス転換した瞬間を祝う演出=W1)/ 月別・年別成績グラフ / 戦略タグ別成績(どの手法が機能しているか)
- W2: 「期待値がプラスのトレーダーは少数派。あなたは今 ◯◯円/回」
- W3: 月次成績カード画像(金額非表示モードあり)
- W5: 保有期間別分析・曜日別分析
### 技術
積み立てエンジン(20_tsumitate)を流用(entries=トレード)。**金融ツール群だが技術的には tsumitate-apps モノレポに置く**
### 指示例: `SPEC.md §C4。tsumitateエンジン流用、Entryをトレード型に拡張`

## §C5. ストックアラーム(stock-alarm)【製品=テンプレリポジトリ+記事】

**一言**: サーバー代ゼロの自分専用・株価アラート基盤
### 設計(個人ツール配布モデル)
- マルチユーザーSaaSにはしない(通知サーバー=維持費)。**「forkして自分のリポジトリで動かす」テンプレート**として完成させ、note記事(セットアップ手順)とセットで販売 or 無料公開+サポート有料
- 構成: `config.yaml`(銘柄/条件)→ GitHub Actions cron(平日16:00 JST)→ yfinance終値取得 → 条件判定 → **Discord Webhook通知**(LINE Notifyは終了済みのため不使用。代替: Discord/ntfy.sh/メールの3方式実装)
- 条件タイプv1: 終値が指定値以上/以下・配当利回り到達・RSI(14)閾値・MA乖離率・ゴールデンクロス。日本株/米国株両対応
- トレード結果の追記(results.csv)→ Actions が月次サマリ(条件タイプ別勝率)をissueに自動投稿
### ⚠️ 確認
- Actions cron の遅延特性(指定時刻±数十分ブレる)を明記し、ザラ場判定には使わない設計とする
- private repo の Actions 無料枠(分数)で月間消費が収まるか試算を記録
### 受け入れ条件
fork→config編集→Secrets設定→初回通知まで**15分で完了する README** が成果物の本体
### 指示例: `SPEC.md §C5。READMEのセットアップ手順を最重要成果物として作り込む`
