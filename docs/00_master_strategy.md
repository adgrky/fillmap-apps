# アプリポートフォリオ総合戦略書(マスタープラン)

> 本書+シリーズ別設計書(10/20/30番台)で全アプリを管理する。
> 各リポジトリには該当する設計書のみを `docs/SPEC.md` として配置。
> Claude Code への指示は常に「SPEC.md §X を実装」形式(仕様の再記述禁止=トークン節約)。

---

## §1. 全体戦略:個別アプリではなく「工場」を作る

数撃ちゃ戦略の本質は「1本あたりの製造コストを限界まで下げること」。
そのために**3つの共通エンジン**を最初に作り、以降はデータとテーマの差し替えで量産する。

| エンジン | 設計書 | 量産できるアプリ |
|---|---|---|
| 埋め立てエンジン(地図×塗り) | 10_fillmap_series.md | 路線/百名山/市区町村/道の駅/100名城/国道/温泉/空港・離島/マンホール/御朱印/SA・PA/街道 |
| 積み立てエンジン(記録×成長可視化) | 20_tsumitate_series.md | 勉強/ギター練習/ちょちく/投信つみたて/新NISA/好きなこと発見 |
| 金融ツール群(yfinance×Streamlit / Actions) | 30_finance_tools.md | 米国株リサーチャー/配当カレンダー/割安診断/収支管理/ストックアラーム |

### 共通技術原則(全アプリ)
1. **維持費0円**: 静的PWA(GitHub Pages)or Streamlit Community Cloud or GitHub Actions のみ
2. **データはユーザーの端末に**: localStorage/IndexedDB + JSONエクスポート/インポート必須
3. **シェア画像が広告**: 全アプリにクライアント側Canvas生成のシェア画像機能を標準搭載
4. **称号エンジン共通化**: 定義JSONを差し替えるだけで全アプリに実績システムが載る
5. デザイントークンは railmap SPEC §6 を全アプリ共通の基底とし、アプリごとにアクセント色だけ変える

### 勝ちルート5原則(全アプリの設計に必ず適用)
各アプリ設計書では、この5項目を必ず具体化して記述している:
- **W1 塗る/積む瞬間の快感**(アニメ・効果音・カウントアップ)
- **W2 数字の感情化**(換算文言・多層達成率・「あと少し」の常設)
- **W3 シェア画像=広告**(美しい成果画像をワンタップ生成)
- **W4 信頼設計**(ローカル保存明言・バックアップ・オフライン動作)
- **W5 マニアの深み**(有料化の種になるニッチ機能)

## §3. 共通ブランド戦略

- シリーズ名を統一する: 埋め立て系は「◯◯埋め立てマップ」、積み立て系は「◯◯つみたて」で命名統一 → 1本ヒットすれば横流入が起きる
- 全アプリのフッター/設定画面に「シリーズ一覧」リンク(静的リンク集ページを1枚作る。これがポータルになる)
- シェア画像の右下ロゴ・URL表記のフォーマットを全アプリ統一(ブランド認知の蓄積)
- X運用: アプリごとにタグを固定(#路線埋め立て 等)。開発過程も発信する(個人開発クラスタは過程に反応する)

## §4. 収益化方針(共通)

| 段階 | 手段 |
|---|---|
| v1 | 完全無料で配布、ユーザー獲得最優先 |
| 反応あり | TWA化してPlay Store買い切り(¥300-800)。Web版は機能制限版として残す |
| マニア機能 | 各SPECの「W5」に記載の深掘り機能をプレミアムに |
| 副産物 | 「個人開発でゼロ円運用アプリ群を作る方法」note記事/テンプレ販売(ストックアラームはこれが本体) |

## §5. Claude Code 共通運用ルール(全リポジトリ共通、初回に1度渡す)

```
唯一の仕様書は docs/SPEC.md。仕様にない実装・ライブラリ追加・デザイン変更は禁止。
曖昧なら実装前に質問。実データ・実設定値を確認してから書く(推測禁止)。
タスク完了時 PROGRESS.md に3行以内で記録。回答は変更点のみ簡潔に。
共通エンジンは packages/core として独立させ、アプリ側から import する。
```

### モノレポ構成(埋め立て系・積み立て系それぞれ1リポジトリ)

## §7. 新規アイデアの受付プロセス(恒久ルール)

新しいアプリ案は思いついた時点で `docs/IDEAS.md` に追記し、**5分トリアージ**にかける。

### 7-1. トリアージ(順に判定、落ちたら止まる)
1. **維持費ゼロで作れるか?** No → 「却下箱」へ(理由1行を残す。将来環境が変われば復活あり)
2. **既存エンジン(埋め立て/積み立て/金融)に載るか?**
   - 載る → 量産リストへ。§7-2のスコアで順番決め
   - 載らない → 「第4エンジン候補箱」へ保留。**同型アイデアが3つ溜まった時点で新エンジン化を検討する(1本のためにエンジンは作らない。3本作れるなら工場を建てる)**
3. **勝ち筋W1〜W5のうち3つ以上を具体的に書けるか?** 書けない → 寝かせ箱(機能はあっても愛されない)

### 7-2. スコアリング(リリース順の唯一の物差し)
`スコア = 流用度(3:エンジンそのまま/2:小改修/1:大改修) + 市場熱(3:シェア文化が強いクラスタあり〜1:不明) + 時事性(2:いま検索される〜0:常緑)`
同点は工数が短い方を先に。

### 7-3. IDEAS.md テンプレ
```
## アイデア名(YYYY-MM-DD)
一言: / エンジン: 埋立|積立|金融|第4候補 / スコア: 流用◯+市場◯+時事◯=◯
勝ち筋メモ: W1: W2: W3:
判定: 量産リスト入り | 第4候補箱 | 寝かせ | 却下(理由)
```

## §8. 戦略成長基盤(最初から実装する)

> 以下はフェーズ1で railmap と並行して構築する「戦略自体を賢くする」インフラ。
> 各項目に Claude Code への指示例を付す。**ケン自身の作業(アカウント作成等)は[👤ケン]と明記**。

### 8-1. 計測基盤(最優先)
- 全アプリに **GoatCounter**(軽量・無料・Cookieレス)の計測スニペットを標準搭載
- [👤ケン] GoatCounter のアカウント作成とサイトコード取得(⚠️無料枠の利用規約=個人/非商用条件を確認し、有償化フェーズで Plausible 等への移行要否を判断。確認結果を VERIFIED.md へ)
- 実装: packages/core に `analytics.ts`(サイトコードはアプリ設定で注入。未設定なら何も送らない)。**計測はPVのみ。個人データ・操作内容は送らない**(W4信頼設計と整合。プライバシー文言に計測の記載を追加)
- 判断基準の固定: 公開14日間の「PV/ユニーク/X最高インプレ」を §8-2 のダッシュボードに記録し、シリーズ内相対比較で次の投資先を決める
- 指示例: `00_master §8-1 を実装。analytics.ts は core に、設定未注入時は完全無効`

### 8-2. ポートフォリオ管理ダッシュボード(自分用アプリ pfdash)
- 全アプリの「公開日 / 14日PV / X反応 / 状態(開発中・公開・集中・凍結)/ 次アクション」を一覧するローカルPWA。**積み立てエンジンを流用して作る**(=ドッグフーディング。使って感じた不満は packages/core の改善チケットにする)
- v1: 手入力+CSV入出力のみ。v2: GoatCounter API からPV自動取得(⚠️APIのCORS可否を確認してから設計)
- 指示例: `20_tsumitate のエンジン流用で pfdash を実装。Entry=アプリ計測値。00_master §8-2参照`

### 8-3. エンジン改善デー(プロセスルール)
- 月1日、機能追加を止めて **横断資産(シェア画像の見栄え/塗りアニメの質/称号演出/起動速度)だけを磨く日** を設ける。改善は全アプリに波及する=1の労力がN倍になる複利日
- 改善対象は pfdash の不満メモと §8-6 のユーザー要望から選ぶ
- 指示例: `本日はエンジン改善デー。対象は◯◯のみ。アプリ固有コードへの変更禁止`

### 8-4. 量産スキャフォールド
- `tools/create_app.py <engine> <appId> <アプリ名>`: テンプレアプリをコピーし、ID・名称・テーマ色・manifest を一括置換、deploy.yml にエントリ追加まで自動化
- 受け入れ条件: **curated CSV と称号定義を用意した状態から、公開可能ビルドまで人手30分以内**
- 指示例: `00_master §8-4 のスキャフォールドを実装。受け入れ条件は30分基準`

### 8-5. シリーズポータル(ブランド複利)
- `apps/portal`: 全アプリのカード一覧(アイコン/一言/リンク)を載せた静的1ページ。データ源は `apps.json` 1ファイル(スキャフォールドが自動追記)
- 全アプリのフッター「シリーズ一覧」と、シェア画像の統一URLはここを指す。**N本目のアプリがN-1本分の追い風を受ける**導線
- 指示例: `00_master §8-5 のポータルを実装。apps.json 駆動で手作業ゼロ`

### 8-6. フィードバック回路
- [👤ケン] Googleフォーム(要望・不具合・1問+自由記述)をアプリごとに作成しURLを発行
- 実装: 設定画面に「ご意見・要望」リンクを標準枠として設置(URLはアプリ設定で注入)
- 寄せられた要望は IDEAS.md(機能要望はW5候補)へ転記して資産化
- 指示例: `設定画面にフィードバックリンク枠を core 実装。URL未設定時は非表示`

### 8-7. 月次レトロスペクティブ(戦略のバージョン管理)
- 毎月末、`docs/PORTFOLIO.md` に5行追記: ①今月出したもの ②数字(pfdashから)③一番の学び ④来月の集中先 ⑤§6ロードマップの□更新
- [👤ケン] カレンダーに月末リマインダー登録
- このファイルの履歴が「戦略のバージョンアップ履歴」そのものになる

### 8-8. note素材ログ(知見の商品化)
- 開発過程の「やったこと・詰まったこと・解決法」を**作業のたびに自動蓄積**する仕組み。詳細仕様と Claude Code への組み込み方法は別紙 `41_notelog_spec.md` に定義(全リポジトリ必須)
